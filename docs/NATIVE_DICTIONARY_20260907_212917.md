# 원천 기반 영한·한영 사전

2026-09-07. 새 구조는 영어판 Wiktionary의 뜻에 한국어 뜻을 매칭하는 것을 선행조건으로 삼지 않는다.

## 제품 구조

- 기본 `/`: 한국어판 Wiktionary 영어 항목의 한국어 뜻을 보여 주는 영한 검색, 한국어기초사전 원문을 보여 주는 한영 검색.
- 영어 기본 뜻이 없으면 한국어기초사전의 영어 대응표현 검색을 별도 영역으로 펼친다. 이 관계를 Wiktionary 뜻의 exact 번역으로 만들지 않는다.
- 영어판 Wiktionary는 별도의 영영 원문 링크로 제공한다.
- `/legacy_20260907_205800.html`: 기존 검색 화면과 공개 exact208을 보존한다. 기존 app·원천·검토 결과를 삭제하거나 새 원천으로 재분류하지 않는다.
- 기존 공유 주소 `?q=`를 유지하고 입력 언어로 검색 방향을 자동 판별한다. 방향 선택 버튼은 없으며 이전 `direction` 파라미터는 검색 방향을 강제하지 않는다. 검색 성공 알림은 화면 공간을 차지하지 않고 접근성 알림으로 제공한다.

## 입력과 공통 교정

2026-09-08 교정에서는 Kaikki 추출본과 별도로 공식 한국어판 20260901 XML을 확보하고, 원문 본문·품사 제목·언어 구역과 구형 틀을 처리하는 추출기를 수정했다. `tree`와 같은 본문 기본 뜻이 뒤의 품사 항목 때문에 빠지던 공통 조건을 고친 전체 추출본을 사용한다. 기존 raw·샤드·tree 보완 파일은 보존하되 개별 tree 보완 import는 새 전체 자료에서 제거한다. 최종 수량·실행·전수 차이는 [공통 교정 보고서](DATA_SOURCE_CORRECTION_20260908_014922.md)를 따른다.

원표제어와 뜻 경계를 유지한다. 공백·Unicode를 정규화하고 검색키는 소문자로 찾되, `US`와 `us`처럼 대소문자가 의미를 구별하면 정확 표제어 일치를 우선한다. 정확한 대소문자 표제어가 없으면 동일 검색키의 원표제어 후보를 각각 표시한다. 품사를 추정하지 않고 예문만의 한국어를 정의로 승격하지 않는다. 추출 오류와 한국어 풀이 없는 항목은 원시 자료에 보존하면서 제품 표시 여부를 별도로 기록한다.

한국어기초사전은 공식 전체 ZIP을 새로 확보해 한국어/영어 원문 전용 자료를 재생성했다. 한국어51,909검색키·76,833뜻의 핵심 정보를 유지하고 예문657,691텍스트·주석·발음·관계를 복구했다. core와 역검색은 각각64샤드, 상세는256샤드이며 상세는 사용자가 펼칠 때만 가져온다. 기존 compact 자료는 이전 검색과 기록에 남는다.

영어 역검색은49,047키·107,501연결이며30,888개 구 검색키를 포함한다. entity를 복원한 뒤 세미콜론 대안을 나누며 쉼표/슬래시 혼합구의 모호한 부분을 임의로 별도 단어로 만들지 않는다. 따라서 일부 이전 조각 키는 원문 전체 표현으로만 조회할 수 있다. 영어 대응표현 검색은 한국어 원문의 연결을 보여 주며 영어판 뜻에 대한 exact 번역으로 해석하지 않는다.

한영 결과는 용법과 발음을 표시하고 예문·관련 표현은 접힌 상세로 제공한다. 예문은 원문 그룹8개씩 더 볼 수 있다. 원천 공통 필드와 한국어/영어 상세를 보존하며 다른 언어의 대응표현은 원본 ZIP에 남긴다.

## 이전 검색

이전 영어판 검색은 상위 뜻의 ID·본문·번역 연결을 보존하면서 화면용 하위 뜻 계층을 추가한다. 품사별8개 이후는 더보기로 이어지고 추가 품사와 정의 목록도 읽는다. US/us의 캐시는 구분한다. 녹음은 Wikimedia Commons 파일별 출처·이용 조건으로 연결하고 기기 합성 음성과 구분한다. 새 하위 뜻에 기존208개 연결을 자동으로 복사하지 않는다.

## 실행과 점검

기존 Worker·계정·도메인·비밀값·배포 설정은 변경하지 않는다. 새 기본 검색은 같은 도메인의 정적 사전 자료만 읽는다. 기존 `/api/lookup`은 이전 검색에서 계속 사용한다. 새 정적 화면은 로컬 정적 서버에서도 확인할 수 있다. 이전 검색 API까지 확인하려면 기존 Worker 개발 환경을 사용한다.

배포 대상 checkout에서 `npm run verify`를 사용한다. 이전 화면의 기존 기능 검사는 HTML fixture를 보존된 legacy 페이지로 읽고, 새 화면 검사는 활성 index와 실제 새 loader를 읽는다. 실제 운영 반영과 브라우저 확인 결과의 정본은 `docs/PROJECT_STATE.md`를 따른다.
